# Контекст проекта

Исследовательский sandbox: понять фактическое поведение inference pipeline YOLO26/Ultralytics и подготовить независимую реализацию по наблюдаемому поведению и публичным интерфейсам.

## Обязательные правила

- Всегда сначала читать этот файл. Документацию читать по необходимости, не загружать всё подряд.
- Не читать, не выводить и не передавать `.env*`, ключи, токены, credentials, логи, дампы, клиентские данные, PII и внутренние конфигурации. При обнаружении — остановиться и сообщить пользователю.
- Не читать игнорируемые локальные документы без явного подтверждения, что они санитизированы.
- Перед подключением реального репозитория проверить `.gitignore` и agent-specific ignore; рекомендовать TruffleHog/Gitleaks для рабочего дерева и git history.
- Не копировать, не портировать и не адаптировать исходный код Ultralytics. Исследовать публичные интерфейсы, архитектурные границы и наблюдаемое поведение; спецификацию и продуктовый код формулировать независимо.
- Лицензию Ultralytics, весов и сторонних tracker-компонентов проверять отдельно с ответственным за legal/compliance. Не делать юридических выводов только по техническому анализу.
- Не реализовывать будущую задачу без явного запроса. Сейчас приоритет — исследование и объяснение.
- Ориентироваться на фактически установленную версию, не угадывать API/методы. Сначала находить определение и точку вызова, затем подтверждать минимальным экспериментом.
- Перед изменениями изучать контекст; не менять несвязанные файлы. Опасные или внешние действия сначала согласовывать. После изменений выполнять минимально достаточную проверку.
- Документацию и объяснения вести по-русски; комментарии и литералы в коде — по-английски. В итогах указывать изменённые пути и непроверенные допущения.

## Границы исследования

В scope: preprocessing, inference/backend execution, postprocessing, tracking, поток одного кадра, shapes/dtypes/devices, основные классы и настройки, структура результатов, границы этапов.

Вне scope: training, loss-функции, глубокий разбор архитектуры сети, GPU-оптимизация, крупные рефакторинги и преждевременная собственная реализация.

## Метод исследования

1. Зафиксировать версию Python/Ultralytics/PyTorch, модель/weights, backend и способ запуска проекта.
2. Построить карту публичный entry point → predictor → source loader → preprocess → model/backend → postprocess → `Results`.
3. Для каждого этапа фиксировать вход/выход: Python-тип, shape, dtype, диапазон значений, device, настройки и место в коде.
4. Проследить один image и один video frame небольшими read-only probes/hooks; не копировать тела методов.
5. Отдельно исследовать tracking: регистрация callbacks, lifecycle tracker, association, persist/reset и связь track IDs с `Results`.
6. Итогом подготовить карту файлов для чтения, таблицу настроек, схему data flow и вопросы команде.

## Текущее состояние

- Ветка `main` синхронизирована с публичным `origin`: `https://github.com/A7med373/yolo_sandbox`.
- Исследовательское окружение: `.venv`, Python 3.10.12, Ultralytics 8.4.115, PyTorch 2.13.0, torchvision 0.28.0, OpenCV 5.0.0, lap 0.5.13.
- Проверенный baseline: `yolo26n.pt`, detect, PyTorch CPU; MPS недоступен. Веса, публичные test media, caches и `.venv/` исключены через `.gitignore`.
- `examples/predict_cpu.py`: фактические классы `YOLO` → `DetectionPredictor` → `Results` → `Boxes`; на test image `Boxes.data` имеет `(5, 6)`, `float32`, CPU.
- `examples/track_cpu.py`: default tracker — `tracktrack.yaml`, класс `TRACKTRACK`; tracked `Boxes.data` имеет 7 столбцов и доступный `Boxes.id`.
- Реальные project task, checkpoint, deployment backend, режим `end2end` и требования к tracking пока не подтверждены.

## Полезные безопасные команды

- `rg --files -uu` — инвентаризация файлов (до чтения проверить чувствительные пути).
- `.venv/bin/python -c "import sys; print(sys.executable); print(sys.version)"` — проверить интерпретатор.
- `.venv/bin/python -m pip show ultralytics torch` — проверить установленные версии в выбранном окружении.
- `.venv/bin/python -c "import ultralytics; print(ultralytics.__version__); print(ultralytics.__file__)"` — подтвердить версию и путь пакета.
- `.venv/bin/python examples/predict_cpu.py` — минимальный detection на CPU.
- `.venv/bin/python examples/track_cpu.py --frames 20` — минимальный tracking на CPU.

Обновлять этот файл после подтверждения окружения и завершения каждого существенного этапа исследования; хранить здесь только устойчивые факты и следующие шаги.
